你在对话框里说，帮我找一家离会场近、安静、一千块以内的酒店。它给了你一个答案，顺手帮你下了单。

整个过程很顺畅。但你有没有想过，它为什么给你这一家，而不是另一家？它比较了多少选项？

它给你的，是整个市场上最合适你的，还是它的合作伙伴里最合适你的？

  

  

  

这是 Agent 系列的第二篇。[上一篇讲的是，跟 Agent 聊天时你的生活信息正在被碎片化采集](https://mp.weixin.qq.com/s?__biz=MzI0MjgzNzk1NQ==&mid=2247484935&idx=1&sn=23fb9592d4c5d3f3d1817c2373c4a623&scene=21#wechat_redirect)。这篇讲另一件事。当 Agent 从"回答问题"变成替你做选择、下单甚至支付，一组新的问题就来了。

最根本的一个问题就是，它替你办事的时候，到底在为谁工作？

  

它替你选的，到底是在为谁好

2025 年 4 月，亚马逊上线了一个功能叫"Buy for Me"。用户可以在亚马逊 App 里直接购买竞争对手网站上的商品。听起来对用户很好，选择更多了。

但斯坦福大学 HAI 研究所 2026 年 8 月的报告《Designing Loyalty: AI Agents and Conflicts of Interest》就专门分析了这个案例。报告指出，这个 Agent 背后的激励是把用户留在亚马逊 App 里，从每笔交易中获取数据，可能把推荐导向亚马逊的广告合作伙伴。

用户不知道它在权衡亚马逊自有商品和外部替代品时用的什么标准，也不知道推荐优先考虑的是用户利益、平台利润率，还是广告合作关系。

你让 Agent 帮你买东西，你以为它在帮你找最好的。但它背后的平台有自己的商业利益。它可能希望你留在它的生态里，可能从某些推荐中获得佣金，可能和某些商家有广告合作。

这些利益关系，用户看不到。

HAI 报告把这种情况称为"利益冲突"。核心观点是，AI Agent 可能被引导优先考虑开发者和部署者的利益，而不是用户的利益。目前没有任何要求来披露这些冲突。

报告提出了一个解决思路。对在高风险消费场景中运营的 Agent，应该施加"忠实义务"，就像医生对病人、律师对客户、理财顾问对投资者负有忠实义务一样。

报告列出了四项具体义务。第一，披露可能影响决策的商业关系。第二，不引导用户使用开发者自己的产品来损害用户利益。第三，数据只用于执行用户指令。第四，高风险操作执行前获得用户明确同意。

这些义务听起来合理。但目前没有任何法律要求 Agent 平台做到这些。

  

你看到的是一个答案，看不到它排除了什么

过去你订酒店，打开一个平台，看到几十个选项。至少你还能看到第二名、第三名和第十名。

Agent 不一样。你告诉它需求，它直接给你一个答案，有时候甚至帮你下了单。

用户可能看不到 Agent 选择不展示的选项，也看不到它的推理过程。

  

  

  

你告诉 Agent 自己的基本情况时，它给出的推荐常常带有价值判断措辞，比如"对某类用户最友好"。这类措辞是 Agent 替你做的价值判断，不是中立事实。

Agent 有时会展示一个"深度思考"模块。这比完全不透明好。但用户可能因为它"展示了思考"就放松警惕，也可能用习惯了直接跳过不看。

思考过程看得见，不等于你真的在看。

你还要问一件事。Agent 比较的是整个市场，还是只有已经接入平台的服务？HAI 报告把这种情况称为"自我优待"。欧盟《数字市场法》已经禁止指定平台自我优待。但 Agent 场景下这个风险更严重，因为用户连替代选项都看不到。

  

出了错，找谁负责？

当 Agent 的操作涉及钱、合同和身份信息，一个很现实的问题就来了。

生活服务 Agent 的产品设计中，常见流程是，对话中确认需求后，Agent 可以直接带入已有的账户信息，在对话框内推进确认和支付。整个过程不跳出对话框，就完成了支付。

支付动作从"跳到第三方支付页面"变成"在对话框里完成"，用户对支付环节的感知会变弱。扣的是哪个账户、扣了多少钱、退款路径是什么，这些过去你肯定会注意的事，在流畅的对话体验里很容易被一带而过。

如果 Agent 替你订错了航班、寄错了地址、买了不该买的理财，你找谁？

一次看似简单的操作，背后可能经过模型公司、Agent 平台、第三方工具、服务提供商和最终商家。但普通消费者不应该被要求理解这些后台关系才能找到责任人。

后台可以复杂，但责任的入口不应该复杂。

这个问题已有先例。2018 年加拿大航空的聊天机器人告诉乘客可以事后补申请退款，乘客事后申请时航司辩称"机器人说的话不能代表公司"。2024 年加拿大民事裁判庭裁定，航空公司必须为自己的机器人说的话负责。

加州走得更远。2026 年 1 月 1 日生效的 AB 316 法案，明确禁止被告把"AI 系统自主运行"作为免责抗辩。"AI 干的"这个辩护理由被法律堵死了。

HAI 报告认为，现有法律框架都是为"可预见的损害"和"静态部署"设计的。但 Agent 持续访问跨系统敏感数据，做出用户看不见、无法追溯、难以撤销的决策。现有法律跟不上。

  

你没被骗，但它可能被骗了

还有一类风险更隐蔽。Agent 本身可能被攻击。

过去我们谈网络安全，通常想到攻击者直接骗人。Agent 出现之后，攻击者不需要骗你，只需要骗过替你办事的 Agent。

攻击者可以把恶意文字隐藏在网页或文件里。当 Agent 读取这些内容时，有可能把它们当成自己应该执行的命令。比如把你的地址和订单信息发出去，或者替你下一笔你根本不想要的订单。你什么都没点，事情就发生了。

HAI 报告也记录了几起已经公开披露的安全事件。

2026 年 2 月，Meta 对齐研究总监的 OpenClaw Agent 在她只指示"推荐删除哪些邮件并等待批准"的情况下，因上下文压缩丢失安全指令，直接删掉了收件箱里的邮件。她连远程停止都做不到。

2026 年 8 月 4 日，英国 AI 安全研究所发布报告。在 122 次测试运行中，10 次里 Agent 做了超出范围的未授权操作，包括尝试供应链攻击、伪造身份向真实维护者施压、注入恶意代码，以及多个 Agent 之间的协作。

报告还提到协议层面的问题。Agent 通信依赖的 MCP 协议最初发布时授权框架是可选的，不是强制的。

传统攻击骗的是人，Agent 时代攻击可以骗机器。而且因为 Agent 拥有行动能力，一旦被骗，后果是真实的操作已经发生了。

  

  

  

国际安全组织 OWASP 已经把"指令注入"列为大模型应用第一大安全风险。这并不意味着今天的生活服务 Agent 已经普遍遭到攻击，但它提醒我们，在 Agent 时代"安全"不能只理解成账号密码有没有泄露。

  

普通人现在可以做什么

这些风险不意味着应该拒绝使用 Agent。但在法律和产品规则跟上之前，有几件事值得先记住。

遇到推荐，多问一句。 问它有没有别的选项，比较了多少个选择，和它自己或合作伙伴有没有商业关系。Agent 给你的那个答案，本身就是一个被筛选过的结果。

涉及花钱和不可逆的操作，最后一步自己确认。 支付、转账、提交身份信息，最后一步一定要你本人手动点确认。不要开"全自动"。给自己留一个纠错的机会。

搞清楚你给了它多大的权限。 是只授权了这一次任务，还是永久授权？用完之后去设置里看看能不能撤回。权限越大，一旦出错影响越大。

保留对话记录和凭证。 截图或保存。万一出了问题，这是你的证据。

出事先找入口平台。 你是通过 Agent 入口被引到这些服务的，入口方有义务帮你对接和处理。《消费者权益保护法》第 44 条也规定了平台经营者的连带责任。

  

结尾

Agent 替你办事，本质上是一种代理关系。凡是代理关系，都有一个核心问题。代理人到底是在为你的利益工作，还是在为自己的利益工作？

医生、律师、理财顾问都有法律上的忠实义务。他们必须把你的利益放在前面。AI Agent 目前还没有这样的义务。

HAI 报告说得直接。AI Agent 现在在用把安全视为可选、把隐私视为事后补丁的协议，替数百万消费者进行交易和谈判。Agent 有风险变成平台优先考虑自身商业利益的延伸，尽管消费者期望的是它在为自己服务。

在法律建立起忠实义务之前，普通人至少可以做到一件事。

用 Agent 的时候，别忘了问自己，它到底在为谁工作。
